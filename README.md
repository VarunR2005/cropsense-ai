# CropSense AI: Crop Yield Prediction & Smart Farming

CropSense AI is a student web application that helps farmers estimate crop yields, choose suitable crops,
plan fertilizer and irrigation, check weather alerts, and export reports. It uses machine learning where a
suitable model exists, and documented agronomic rules where it does not.

> **Status:** Core features are built and tested. **Plant disease detection is not built yet.** The page
> says so, and the API has no disease endpoint, so the app never shows a fake result.

---

## Features

| Feature | What it does | How it works |
|---|---|---|
| **Accounts** | Register, log in, log out, edit profile, change password | JWT tokens, bcrypt password hashing |
| **Crop yield prediction** | Predicts yield (t/ha) and total production for a district, crop, season and area | Random Forest Regressor trained on district-level data, 1997-2015. Compared with historical averages |
| **Crop recommendation** | Ranks the top 3 crops from soil N, P, K, pH and weather | Random Forest Classifier with suitability scores and typical growing ranges |
| **Fertilizer recommendation** | Fertilizer quantities in kg/ha for a crop and soil test | Rule-based nutrient calculation. Each line shows its reasoning |
| **Weather forecast** | Current weather and a 5-day outlook, with farming alerts | OpenWeatherMap free API, cached in PostgreSQL |
| **Irrigation planner** | Daily soil-water balance and suggested irrigation dates | FAO-56 method (Hargreaves ET₀, crop coefficients, root-zone water balance) |
| **Dashboard** | Your totals, recent predictions, charts, weather card | Calculated only from your own saved records |
| **Reports** | Regional and farm-level reports with charts and tables | Export as CSV or PDF. Every report states its data source and date |
| **Plant disease detection** | _Not built yet_ | Planned. See "Roadmap" |

## Setup

You need **Python 3.14** (or 3.12), **Node.js 20+**, and **PostgreSQL 17**.

### 1. Database

Create a database user and database (using `psql` or pgAdmin):

```sql
CREATE USER cropsense_user WITH PASSWORD 'choose-a-strong-password';
CREATE DATABASE cropsense OWNER cropsense_user;
```

### 2. Backend

```powershell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1        # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env             # macOS/Linux: cp .env.example .env
```

Edit `.env`:

```
DATABASE_URL=postgresql+psycopg2://cropsense_user:YOUR_PASSWORD@localhost:5432/cropsense
SECRET_KEY=generate-one-with-the-command-below
OPENWEATHER_API_KEY=your-free-key
```

Generate a secret key:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Create the tables:

```powershell
alembic upgrade head
```

### 3. Datasets and trained models

The datasets are not included. Download them from Kaggle and save them with these exact names:

| File | Dataset | Save as |
|---|---|---|
| District crop production | "Crop Production in India" (Abhinand) | `backend/datasets/crop_production.csv` |
| Crop recommendation | "Crop Recommendation Dataset" | `backend/datasets/crop_recommendation.csv` |

Then train the models:

```powershell
python -m app.ml.train_yield
python -m app.ml.train_crop_recommender
```

Each script prints its evaluation metrics. The trained files are saved to `backend/trained_models/`.

### 4. Run the backend

```powershell
uvicorn app.main:app --reload
```

Open the interactive API documentation at **http://localhost:8000/docs**.

### 5. Frontend

In a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Open **http://localhost:5173**. Keep both terminals running while you use the app.

### 6. Tests

```powershell
cd backend
python -m pytest -q          # backend: auth, ML, routes, reports, dashboard

cd ../frontend
npm test                     # frontend: API client, dashboard, login
```

## API overview

All endpoints except registration, login and health need a bearer token from `/api/auth/login`.

| Area | Method and path | Purpose |
|---|---|---|
| Health | `GET /api/health` | Check the server is running |
| Auth | `POST /api/auth/register` | Create an account |
| | `POST /api/auth/login` | Get an access token |
| | `GET /api/auth/me` | Current user |
| | `PATCH /api/auth/me` | Update your name |
| | `POST /api/auth/change-password` | Change password |
| Yield | `GET /api/predictions/options` | Valid states, districts, crops, seasons and model metrics |
| | `POST /api/predictions/yield` | Predict yield |
| | `GET /api/predictions/history` | Your past predictions |
| Crop recommendation | `POST /api/recommendations/crops` | Top 3 crops |
| | `GET /api/recommendations/history` | Your past recommendations |
| Fertilizer | `GET /api/recommendations/fertilizer/crops` | Supported crops |
| | `POST /api/recommendations/fertilizer` | Fertilizer quantities |
| Weather | `GET /api/weather/forecast?city=` | Current weather, 5-day outlook, alerts |
| Irrigation | `GET /api/irrigation/crops` | Supported crops |
| | `POST /api/irrigation/recommend` | Irrigation plan |
| | `GET /api/irrigation/history` | Your past plans |
| Dashboard | `GET /api/dashboard/summary` | Your totals and charts |
| Reports | `GET /api/reports/yield` | Regional report (`format=json`, `csv` or `pdf`) |
| | `GET /api/reports/farm` | Your saved-predictions report (same formats) |

Example request, yield prediction:

```json
{
  "state": "Karnataka",
  "district": "MYSORE",
  "crop": "Rice",
  "season": "Kharif",
  "year": 2015,
  "area": 5,
  "area_unit": "hectares"
}
```

## Model evaluation

Results are from the author's test runs on the datasets above. Your numbers will match only if you
use the same data and the same scripts.

**Yield model** (trained on 1997-2012, tested on 2013-2015, never seen during training):

| Metric | Model | Baseline (average yield per crop) |
|---|---|---|
| Mean absolute error | 1.16 t/ha | 2.19 t/ha |
| R² | 0.915 | 0.730 |

The model cuts the average error by about 47% against the baseline on unseen years. The high R² is partly
because crops differ a lot in yield. The model is less reliable for low-yielding crops, and it cannot
account for weather, soil or new trends.

**Crop recommender** (random 20% test split): accuracy 99.5%, macro F1 0.995. This dataset is clean and
evenly balanced, so these scores do not show that the model works reliably on real farms.

## Important limitations

- **Estimates only.** Every result shows that it is an estimate. Verify soil tests, fertilizer doses and
  irrigation with local agricultural experts before acting on them.
- **Fertilizer rules are approximate.** The crop doses and soil-test thresholds in
  `backend/app/ml/data/fertilizer_rules.json` are general values. They must be checked against your
  State Agricultural University or ICAR recommendations before use.
- **Irrigation uses simplified FAO-56 methods.** Crop coefficients and rooting depths come from FAO Irrigation
  and Drainage Paper 56. Effective rain (80%) and the rooting-depth rule are the author's assumptions. Forecast
  temperatures give a rough ET₀.
- **Yield model limits.** It uses district and season history only. Soil and weather inputs are saved with
  each prediction, but they are not used by the model. It has no data beyond 2015.
- **Weather alerts are rules of thumb,** not official warnings. Follow the India Meteorological Department.
- **Free API limits.** OpenWeatherMap's free tier has rate limits. Results are cached for 30 minutes.

## Troubleshooting

| Problem | Likely cause and fix |
|---|---|
| `psycopg2` fails to install | Use a Python version with prebuilt packages. Python 3.12 is the safest choice |
| `password authentication failed` | The password in `DATABASE_URL` doesn't match the PostgreSQL user. Reset with `ALTER USER cropsense_user WITH PASSWORD '...';` |
| `Cannot reach the server` in the browser | The backend isn't running. Start `uvicorn app.main:app --reload` |
| `401 Not authenticated` | Log in again with **Authorize** in `/docs`, or log in from the frontend. Tokens last 60 minutes |
| `503` on yield or recommendation | The model isn't trained. Run the training script after placing the CSV in `backend/datasets/` |
| `503` on weather | `OPENWEATHER_API_KEY` is missing from `.env`, or the key is not yet active |
| `404` on weather | The city wasn't found. Add the country code, such as `Mysuru,IN` |
| Regional report shows "No records" | Check the spelling. Use the dropdowns on the Reports page |
| `ModuleNotFoundError: reportlab` | Run `pip install reportlab` inside the activated venv |
| Frontend shows a blank page | Check the terminal running `npm run dev` for errors. Hard-refresh with Ctrl+F5 |
| `Set-ExecutionPolicy` error in PowerShell | Run `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` once |

## Deployment (outline, not yet tested)

These steps are a starting point. They have not been tested for this project.

- **Frontend:** build with `npm run build` and host the `dist/` folder on a static host such as Netlify or
  Vercel. Set `VITE_API_URL` to the public backend address.
- **Backend:** host on a Python-compatible service such as Render or Railway. Use the start command
  `uvicorn app.main:app --host 0.0.0.0 --port $PORT`. Add the `.env` values as environment variables.
- **Database:** use a managed PostgreSQL service and set its connection string as `DATABASE_URL`. Run
  `alembic upgrade head` once after deployment.
- **Trained models** are not stored in Git. Either train them on the server, or upload the generated
  `trained_models/` files as a deployment asset.
- **Before going live:** generate a new `SECRET_KEY`, set `CORS_ORIGINS` to your frontend address, and
  never commit `.env`.
